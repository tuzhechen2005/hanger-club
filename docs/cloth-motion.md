# 衣服动态方法论

本文写的是怎样让挂在衣架上的衣服动起来符合自然物理：会晃、有惯性、彼此不穿模、几秒内停下、画面上没有痕迹。

本文同时是新衣服的接入手册。T 恤是第一件按这套方法做的衣服。以后接入衬衫、卫衣、外套、裙子，都按下面的步骤走。

相关文档：

- Blender 与网页之间的契约：`docs/asset-spec.md`
- Blender 管线：`tools/blender/README.md`
- Blender 调参记录：`docs/blender-research.md`

## 1. 三层分工

衣服的动态分成三层。每层只负责一件事，不能互相替代，也不能重复计算。

| 层 | 负责什么 | 在哪里 | 不负责什么 |
|---|---|---|---|
| **形状** | 衣服在重力下怎么挂（静止垂坠），以及取下、挂回时的大变形 | Blender 离线模拟：`build_tee.py` 生成垂坠，`bake_clips.py` 烘焙动画 | 实时晃动、和别的衣服碰撞 |
| **整体运动** | 衣架怎么走，包括横杆滑动、取下路径、转圈，以及整个衣架绕挂钩的钟摆 | `src/motion/rig.ts` | 布料本身的变形 |
| **二次运动** | 布料相对衣架的滞后、甩动、挤压、和邻居碰撞 | `src/scene/clothProxy.ts`，实时布料代理 | 衣服的基本形状（由第一层给定） |

两条原则：

1. **物理优先，不伪造。** 晃动、甩动、碰撞都要由模拟算出来。不要在着色器里写死"下摆滞后"，也不要用关键帧假装晃动。用户明确否定过"像固体"的效果。
2. **分清编排动作和物理动作。** 货架上衣服从正面转到侧面，是排版设计出来的动作，现实中的衣架不会自己转。这类动作只传一部分惯性给布料（`RAIL_INERTIA`）。手拿起衣服转圈、近看时拖动旋转、换款时飞入飞出，都是真实的物理动作，惯性全额传递。

## 2. 接入一件新衣服

### 2.1 Blender：形状

按 `tools/blender/README.md` 的运行顺序执行。对新衣服有这些要求：

1. **只固定真正压在衣架上的部分。** T 恤固定肩缝；衬衫和外套也是肩缝；吊带裙固定吊带；裤子用夹式衣架，固定腰头。其余部分交给重力。固定得太多，衣服就像"被撑起的壳"（`docs/blender-research.md` 有前车之鉴）。
2. **起始形状按挂好的样子摆。** 求解器对起始条件很敏感。
3. **弱整形约束只用来防止随机姿态。** 约束低了，袖子会随机甩到前面，甩出 19 cm，衣服侧着排列时就会插进邻居衣服里，网页上推不开，只会抖。判断标准：左右对称，侧面厚度不超过货架间距加约 2 cm。货架间距见 `rig.ts` 的 `LAYOUT.far`，目前是 13 cm。
4. **导出遵守契约。**
   - 单位为米，+Y 向上，+Z 朝前，原点在挂钩内顶点。
   - 节点结构为 `HookPivot > Garment, Hanger`。
   - 外层材质叫 `Fabric`，内层叫 `FabricInner`。网页靠这两个名字区分内外层。
   - 衣架木身网格叫 `HangerWood`。网页用它自动判断布料哪些部分压在衣架上。
   - 不能焊接或简化顶点，否则顶点顺序会变，烘焙的形变目标就对不上了。
5. **几何检查必须 0/0**：`audit_geometry.py` 检查衣架穿透和自交，两项都要是 0。

完成后运行 `npm run models`，生成网页用的压缩模型。

### 2.2 网页：选一组布料参数

在 `clothProxy.ts` 里为新面料定义一组 `ClothProfile`。参数含义见第 4 节。可以复制最接近的预设，见第 6 节。

当前代码有两个限制：横杆上所有衣服共用一个网格，布料模拟也只接受一套粒子结构。第一次加入不同版型的衣服时，要改两处：

- `models.ts`：按商品加载对应模型。
- `ClothSim`：每件衣服用自己的粒子结构和参数。粒子在碰撞阶段已经按"第几件衣服、第几个粒子"编号，改起来是局部的。

### 2.3 验收

```bash
npm test                 # 含 clothProxy.test.ts：固定、内外层绑定、匀速不滞后、能停下、60/120 Hz 一致、编排动作不传惯性、碰撞不穿
npm run dev              # 另开一个终端
npm run cloth:check      # 按第 5 节的目标测量，未达标时退出码为 1
```

数值达标之后，还要用眼睛看一遍，见第 5 节的视觉清单。

## 3. 实时布料代理是怎么工作的

每件衣服有一套约 700 个粒子的粗代理，用基于位置的动力学（PBD）模拟。高精度网格在 GPU 上跟随代理变形。表里每一项都写了它防止的是哪种失败，这些失败都实际出现过。

| 做法 | 防止的问题 |
|---|---|
| **粒子生成**：顶点按 `cell` 大小的体素分组，但只有在布料上互相连通的顶点才归入同一组（UV 接缝处的重复顶点先焊接），太小的碎块并入相邻的组。每组一个粒子；布料上的边跨组时就连一条约束，再加两环的弯曲约束 | 只按空间分组时，袖子贴着衣身垂下的地方会和衣身合成一个粒子，袖子被"粘"住甩不起来（用户反馈的"左袖卡在那里"）；前后片也会粘在一起 |
| **自动固定**：离 `HangerWood` 不到 `pinDistance` 的粒子跟衣架刚性一起动 | 换一种衣服就要手写固定区域 |
| **回到垂坠形状的拉力**：从衣架往下由 `goalTop` 递减到 `goalHem`，长度按衣服实际长度计算 | 没有拉力时，衣服会离开 Blender 给的形状；拉力处处一样大时，衣摆不会甩 |
| **局部保持形状**：以分散选出的粒子为中心，取布料上两步以内的邻居为一个区域，每个区域尽量保持为原形状旋转后的样子；区域互相重叠 | 衣服像果冻，快速转动时下半件扭成一团。早期按水平带做，一条带把袖子和衣身锁成一块，袖子没法在袖窿处单独摆动 |
| **相对阻尼**：只衰减相对衣架的速度，另加一点空气阻力 `airDrag` | 衣架匀速滑动时，衣摆被"空气"一直拽在后面，看起来很软 |
| **惯性比例与上限**：衣架的运动只有一部分作为惯性传给布料，其余直接带着布料走；每帧惯性位移有上限 | 一帧时间突然变长或者甩得太狂时，布料被甩飞；编排动作被当成物理动作 |
| **衣服之间碰撞**：空间哈希，非弹性接触，接触时有摩擦。只有处在两件衣服包围盒重叠区内的粒子才参与 | 衣服互相穿过；挤在一起的衣服一直抖；碰撞检测占掉一半计算时间 |
| **接触松弛**：每步只消除 60% 的重叠 | 一次全部推开，会和形状保持、弯曲约束来回顶，静止时停在两个状态之间闪烁，永远进不了休眠 |
| **同一件衣服的自碰撞**：静止时相距较远的粒子之间也做碰撞，只在衣服变形超过 1 cm 时开启 | 前片被邻居推得穿过后片，露出深色里层（截图里的"深色斑"） |
| **碰撞放在每一步的最后** | 弯曲和形状约束把刚推开的布料又拉回重叠位置 |
| **偏移平滑时不碰固定粒子** | 平滑把肩部从衣架上"抬起来" |
| **绑定**：每个顶点按平滑距离核绑到最多 4 个粒子，候选只限本组和布料上相邻的组 | 按格子绑定会在格子边界跳变；只看空间距离时，袖子上的顶点会跟着它贴着的衣身走 |
| **内外层共用绑定**：内层顶点照抄最近外层顶点的绑定 | 内外层只隔 2 mm，绑定稍有不同，大幅晃动时就会交叉 |
| **法线**：每个粒子用邻居做最小二乘，拟合局部变形梯度，在 GPU 上插值后转动法线 | 法线不变时光照不对；直接对插值后的偏移求导，会出现横向条纹 |
| **阴影**：阴影材质也加上同样的偏移 | 阴影还停在没变形的位置，在布料上留下错位的暗块 |
| **固定步长**：按真实时间累计，满 1/60 s 才推进一步 | 120 Hz 屏幕（新 iPhone）上布料快一倍，计算量也翻倍 |
| **自动降档**：每步平均超过 7 ms 时，换成粗 1.35 倍的粒子（约 400 个），只换一次 | 慢手机卡顿 |
| **休眠**：衣架不动且偏移不再变化 30 帧后，停止模拟 | 静止时也一直耗电 |
| **单独的衣架钟摆**：整个衣架绕挂钩摆动，阻尼很大，加速度有上限（`rig.ts`） | 衣架本身摆 30° 以上，显得太晃 |

## 4. 参数

### 4.1 `ClothProfile`（每种面料一组，`clothProxy.ts`）

| 参数 | `JERSEY_TEE` | 含义 | 调大的效果 |
|---|---|---|---|
| `cell` | 0.04 m | 粒子间距（约 700 个粒子） | 粒子变少、更快，动作更粗 |
| `pinDistance` | 0.04 m | 离衣架多近的布料算压在衣架上 | 固定区域变大，上半身更稳 |
| `goalTop` / `goalHem` | 0.3 / 0.04 | 每步拉回垂坠形状的比例，分别是衣架下方和最下沿的值 | 更硬、更快复位 |
| `damping` | 0.95 | 每步保留的相对速度 | 晃得更久 |
| `airDrag` | 0.004 | 每步因空气损失的绝对速度 | 高速移动时衣摆拖得更明显 |
| `inertia` | 1 | 衣架运动中作为惯性传给布料的比例 | 甩得更厉害 |
| `maxInertialStep` | 0.04 m | 每帧最多传多少惯性位移 | 能承受更狂的甩动，也更容易被甩飞 |
| `bend` | 0.6 | 弯曲约束强度 | 面料更挺，折痕更少 |
| `shape` | 0.25 | 局部保持形状的强度 | 更不像果冻，但转圈时甩开得更少 |
| `maxOffset` | 0.08 m | 渲染网格最多偏离垂坠形状多少 | 允许更大的变形 |
| `radius` | 0.018 m | 碰撞半径，约等于半个 `cell` | 衣服之间离得更开，碰撞更费时 |

### 4.2 整体运动（`rig.ts`）

| 常量 | 值 | 含义 |
|---|---|---|
| `SWING_DAMPING` | 8 | 衣架钟摆的阻尼，约为临界阻尼的 0.85 |
| `SWING_MAX_ACCEL` | 5 m/s² | 驱动钟摆的加速度上限，决定用力甩时最多摆多大 |
| `RAIL_INERTIA` | 0.3 | 货架上的编排动作（滑动、转侧面）传给布料的惯性比例 |
| `PENDULUM_LENGTH` | 0.42 m | 等效摆长 |

### 4.3 症状与对应参数

先调整体运动，再调布料。一次只改一个参数，每次都重新跑 `npm run cloth:check`。

| 看到的症状 | 先调 | 再调 |
|---|---|---|
| 整个衣架摆得太大 | `SWING_MAX_ACCEL` 调小 | `SWING_DAMPING` 调大 |
| 布料太软，跟不上衣架 | `RAIL_INERTIA` 调小 | `goalTop` / `goalHem` 调大 |
| 像果冻，转动时扭成一团 | `shape` 调大 | `bend` 调大 |
| 袖子（或某一片）甩不起来、像粘住 | 画出粒子图（正面和侧面），看袖子和衣身是否共用粒子或绑定 | Blender 里袖子是否贴着衣身垂 |
| 停得太慢 | `damping` 调小 | `goalHem` 调大 |
| 转圈时甩不开 | `shape` 调小 | `maxInertialStep` 调大（拿在手里的动作 `inertia` 本来就是 1） |
| 和邻居穿模 | Blender 里衣服太厚，见 2.1 第 3 条 | `radius` 调大 |
| 深色斑块，看到里层 | 检查自碰撞是否开启、内层是否共用绑定 | `maxOffset` 调小 |
| 横向条纹 | 法线是不是直接求导得来的，应改用每个粒子的梯度 | `cell` 调大 |
| 错位的暗块 | 阴影材质有没有加偏移 | |
| 肩部离开衣架 | 平滑时是否跳过了固定粒子，`pinDistance` 是否够大 | |
| 静止时一直在抖，或者停不下来 | 接触是否为非弹性、有没有摩擦，接触松弛（`CONTACT_RELAX`）是否小于 1 | 休眠阈值 |

## 5. 验收标准

### 5.1 数值（`npm run cloth:check`，手机竖屏 390×844）

| 项目 | 目标 | 当前（M4，2026-10-13） |
|---|---|---|
| 加载后的模拟步数，即挤在一起的衣服能否马上静止 | 0 | 0 |
| 静止时最大偏移，来自货架上互相挤压 | ≤ 1 cm | 0 cm |
| 普通滑动的峰值，按每件 95% 分位，包括转侧面时的挤压 | ≤ 7.5 cm | 5.3 cm |
| 滑动后停下 | ≤ 2 s | 1.0 s |
| 取下转圈时衣服甩出 | 3–7.5 cm | 3.7 cm |
| 近看时快速拖转的峰值 | ≤ 7 cm | 4.8 cm |
| 拖转后停下 | ≤ 1.5 s | 0.7 s |
| 静止后的模拟步数 | 0 | 0 |
| 每帧模拟时间，中位数 | ≤ 5 ms | 3.8 ms（p95 5.5 ms），约 700 个粒子 × 6 件 |

手机上的 JavaScript 一般比 M4 慢几倍，需要在真机上确认帧率。

### 5.2 视觉清单

每次改动都要截图看这几个场景：

- 用力甩横杆：没有深色斑，邻居衣服没有被挤皱，肩部贴在衣架上。
- 取下：转圈时衣服有甩开，到位后自然停下。
- 近看拖转：转动时光照会变化，没有条纹，没有跳动。
- 换款飞入飞出、挂回横杆：内外层不交叉，挂回时会和邻居轻轻碰撞。
- 静止：完全不动。

## 6. 面料预设

只有 `JERSEY_TEE` 经过验证。其他几组是按物理直觉给的起点，要按第 5 节的标准重新调。

| 面料 | 与 `JERSEY_TEE` 的不同 |
|---|---|
| 厚卫衣、抓绒 | `goalHem` 0.06，`damping` 0.93，`shape` 0.35，`bend` 0.8，`airDrag` 0.006 |
| 丝、人棉衬衫 | `goalHem` 0.025，`damping` 0.96，`shape` 0.15，`bend` 0.35 |
| 牛仔、帆布外套 | `goalTop` 0.4，`goalHem` 0.08，`shape` 0.5，`bend` 0.9，`inertia` 0.7 |
| 长裙 | `cell` 0.06，`goalHem` 0.03，`maxOffset` 0.12，`shape` 0.2；摆长 `PENDULUM_LENGTH` 按衣长加长 |

## 7. 做不到的事

- 代理比渲染网格粗得多，只能产生晃动、滞后和挤压，**产生不了新的细褶皱**。褶皱来自 Blender 的垂坠和烘焙动画。
- 取下和挂回时，形状由烘焙动画决定，代理在上面叠加惯性；两者都会对运动产生反应，所以惯性效果可能有一点叠加。
- 离开画面的衣服直接保持垂坠形状，不参与模拟。
- 衣架钟摆是刚体模型，没有考虑衣服重量分布的差异。
